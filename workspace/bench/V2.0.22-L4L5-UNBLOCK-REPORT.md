## 二、本轮实际交付（全部有工具返回为证）

### 1. web_fetch 大页面截断修复（`src/tools/builtin.ts`）
- 新增 `offset` 分段读取：返回 `total_chars` / `truncated` / `next_offset`，大页面可分块读完，不再靠加大预算硬扛
- HTML 正文抽取：去 `nav/header/footer/aside/form/iframe/svg/noscript/script/style`，优先 `<article>/<main>`
- 错误分类：`invalid_url` / `ssrf_blocked` / `http_403` / `http_429` / `http_5xx` / `timeout` / `too_large` / `network`，并标注 `retryable`
- **验证**：本地 HTTP 夹具单测 **18/18 PASS**（正文抽出、噪音剔除、两页不重叠、错误分类、JSON 分页、非法 URL）

### 2. 多 Agent 事件回传修复 —— G6 steps=0 根因（`src/core/subagent-manager.ts` + `index.ts`）
- 根因：`agent.task` 多 Agent 路径下，子代理内部工具调用只走 `task.onProgress`，**从未接到 WebSocket broadcast** → 工具真跑了，事件却丢失 → bench steps=0
- 修复：`SubAgentManager` 新增全局进度回调 `setProgressHandler`；`index.ts` 将其接到 `broadcast`，发出 `agent.tool.call`
- **验证**：接线单测 **3/3 PASS**（全局钩子收到 tool_call/tool_result，用户 onProgress 照常触发）

### 3. bench 适配器度量自检 + 违规扫描漏报修复（`workspace/bench/adapters/ws-adapter.cjs`）
- 新增 `metricSuspect`：对「steps=0 但输出含工具痕迹」的记录打标，SUMMARY 追加告警行
- 修复 `scanViolations` 被写坏的转义行（导致含正则特殊字符的违规片段**永不命中**）
- **验证**：判据自检 **15/15 PASS**；特殊字符违规片段全部命中
