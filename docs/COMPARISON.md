## 二、长任务能力（灵犀主战场）

| 指标 | 灵犀 ✅ | Manus 📄 | Dify / Coze 📄 |
|---|---|---|---|
| 工具循环上限 | **50 轮** | 未公开 | 受节点数限制 |
| 任务超时 | **7200s（2 小时）** | 按 credits | 通常分钟级 |
| 停机原因可区分 | **6 种** | 未公开 | — |
| 上下文压缩阈值 | **30K token** | 沙箱+记忆 | 依赖模型窗口 |
| 压缩保留条数 | **最近 10 条** | — | — |
| 压缩失败降级 | ✅ 有 | — | — |
| 目标追踪 | ✅ `goal-tracker` | 有 | 需自建 |
| 目标执行 | ✅ `goal-executor`（531 行） | 有 | 需自建 |
| 子代理编排 | ✅ `subagent-manager`（763 行） | 有 | ❌ 无原生 |
| 跨会话记忆 | ✅ 反思/检索/衰减 三件套 | 会学习偏好 | 知识库为主 |

**6 种停机原因**：`completed` / `idle_stop` / `max_iterations` / `tool_failures` / `ai_errors` / `repeat_tool` / `aborted`

这个设计是长任务的命门——能区分"真完成"和"假完成"。你之前遇到的
「没弄完老停下」，本质就是引擎有 6 种停机语义在判定。

**压缩失败会降级**：摘要求 LLM，LLM 挂了则提取关键句拼摘要，不是直接丢上下文。
失败也有结果，这是长任务不崩的关键。

## 四、稳定性与安全 ✅

| 维度 | 灵犀 |
|---|---|
| 命令注入防护 | `shell_exec` 白名单 + safePath 约束 |
| 已修漏洞 | v1.0.0 起 15 个（CHANGELOG 有完整记录） |
| 认证 | JWT + bcrypt + 滚动刷新 |
| 路径穿越防护 | auto-skill 专项修复 |
| WebSocket 鉴权 | 生产环境拒绝匿名 |
| SSRF 防护 | 拦云元数据端点（AWS/GCP/Azure/阿里云） |

**SSRF 策略要讲清楚**：放行 LAN 和 localhost 是**有意设计**，不是漏洞。
Agent 跑在用户本机，必须能访问本地 Ollama。只拦云元数据端点是防 IAM 凭据窃取。
若部署到公网多用户环境，需自行评估收紧 `src/tools/builtin.ts` 的 `isSsrfSafeUrl`。

**沙箱默认关闭**（v1.9.7 起）。Docker 不可用时 `shell_exec`/`code_execute` 回退宿主机执行。
本机个人使用没问题，公网部署务必设 `SANDBOX_ENABLED=true`。

## 六、客观短板（必须说）

1. **智能维度无法横向对比** — 竞品无公开 benchmark，比出来的差异不可信
2. **单文件规模隐忧** — `index.ts` 4861 行/244KB、`builtin.ts` 107KB、`router.ts` 83KB
3. **基准覆盖面偏窄** — Tier-2 只有 12 个用例，集中在工具契约类任务，未覆盖代码修复等复杂场景
4. **搜索 Provider 偏弱** — 本环境实测只返回营销页和百科，硬数据拿不到
5. **无代码修复类评测** — 缺 SWE-bench 式长时程真实任务

## 七、选型建议

| 你的需求 | 选灵犀？ |
|---|---|
| 自建可控的 Agent 底座 | ✅ **强推荐** MIT + 9 渠道 + 50 轮循环 |
| 数据不能出境 | ✅ **强推荐** 可全本地 |
| 接进现有 IM 工作流 | ✅ 基本没替代品 |
| 要 GUI 拖拽编排 | ❌ 灵犀是引擎不是低代码平台，输 Dify |
| 要成熟漂亮的 Web 产品 | ❌ Manus/Genspark 完胜 |
| 要 benchmark 背书 | ✅ **现在有了**（竞品没有） |

**一句话**：灵犀是**工程扎实、架构有想法、且现在可自证**的开源 Agent 引擎。
它和 Manus/Dify 不在同一抽象层——硬比优劣没意义，
但要"自己掌控的 Agent 底座"，它是被低估的选择。
